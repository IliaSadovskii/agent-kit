# 2.7.0 — one line to add, and two things that start happening on their own

Nothing breaks. A project that changes nothing keeps working: batches still run, the frame child is
written by the commands rather than by you, and the mutation step reports that it did not run.

## The one thing worth doing by hand

Add `commands.mutate` to `.agent-kit/project.yml` — what proves the tests can fail. Without it every
`ship` writes *no such command* into `mutation` and the step is honest and empty; with it, the pull
request finally carries a number that is not the suite reporting on itself.

```yaml
commands:
  test: make test
  mutate: vendor/bin/infection --filter={files}
```

Off-the-shelf per ecosystem: `mutmut` or `cosmic-ray` (Python), `Stryker` (JS, TS, C#), `PIT`
(Java), `infection` (PHP), `go-mutesting`.

`{files}` is the whole of the contract, and it is not decoration: the run replaces it with what
that feature changed against its own base. Inside a batch each feature branches off the last one,
so a command that works out the diff for itself — `origin/main...HEAD` — would hand the last
feature of the night everything the night built. Without the placeholder the tool runs over the
whole project, re-running the suite once per mutation, and a step that takes an hour is a step
every night skips. Whatever you write must also print how many mutants were killed and how many
survived.

`blueprint` proposes this now when it settles the testing section, so a project you take through it
gets the line without you looking any of this up.

## What happens without you

**Batches open with a frame child.** A `sprint` or `epic` batch of three or more now starts with a
child that is not a feature: it reads the batch's entries and the code where two of them meet, and
leaves what those features must build alike as a `[frame …]` block at the end of
`docs/knowledge/stack.md`. `blueprint` folds the block into the map after the batch merges. You will
see one extra session per batch and one extra branch in the chain.

**A blocked feature no longer takes the rest of the batch.** Run files gain `needs` — what a feature
cannot be built *without*, as opposed to what it is built *on top of*. Only that decides skipping
now. Run files written before this release have no such field, and the driver reads that exactly as
it always behaved: the feature before it in the queue. So an old batch resumed with `--resume`
behaves as it did.

## Run files written by 2.6.0 and earlier

They keep working and need no editing. Two fields are new — `needs` and `frame` — and both are
optional; `mutation` is new as well and is asked for only where `commands.mutate` exists.

One cosmetic consequence: until you add the line, every run of the check prints that
`.agent-kit/project.yml` is missing a key the kit's template has. That is the shape check doing its
job, not a fault, and adding `mutate:` — empty or filled — quiets it.
