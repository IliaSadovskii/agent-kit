# 2.0.0 — `mvp` is now `epic`

One command was renamed. Nothing else changed about it: the gate, the batches, the audit in waves,
the finish and the single pull request are the same machinery.

## Why

The command stopped being about the MVP in 1.4.0, when it took a scope: the MVP bounds the first
time, and afterwards whatever is still `planned` or still owed. A name that describes only the first
run of it is a name that lies on every run after.

`epic` was chosen because it explains itself through a command that already exists — `sprint` is a
batch of about five features, `epic` is the whole of what is left, in batches. Nobody has to read a
paragraph to size them against each other.

## What to change

| Before | Now |
|---|---|
| `/agent-kit:mvp` | `/agent-kit:epic` |
| `/agent-kit:mvp --advance <dir>` | `/agent-kit:epic --advance <dir>` |
| `/agent-kit:mvp --resume <dir>` | `/agent-kit:epic --resume <dir>` |
| `check.py --mvp` | `check.py --epic` |
| branch `mvp/<slug>` | branch `epic/<slug>` |
| `"command": "mvp"` in a run file | `"command": "epic"` |

**A run already in flight needs nothing.** The driver still recognises `"command": "mvp"` in a run
file it did not write, so a run left half-finished under the old name is handed back and resumed
exactly as before. New runs write `epic`.

**A branch already called `mvp/<slug>` stays what it is.** The name is written once, when the run
starts; nothing goes looking for the prefix afterwards.

## What was not renamed

**The MVP bounds.** They are a section of `docs/knowledge/product.md`, written by the owner in their
own words, and they mean what they have always meant: the smallest thing worth showing somebody.
`epic` still reads them, and they are still the scope it takes when nothing else is said.
