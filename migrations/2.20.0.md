# 2.20.0 — two lines worth adding, and three things that start being said

Nothing breaks. A project that changes nothing keeps working: every check that was silent yesterday
is silent today unless it found something real, and the two additions below are nudges, not gates.

## The two lines

**A marker above the MVP bounds** in `docs/knowledge/product.md`:

```markdown
<!-- agent-kit:mvp-bounds -->
## Границы MVP
```

The section is your prose under a heading in your own language, and until now the program looked for
it by matching words — which worked only because most headings happen to carry the letters *MVP*.
With the marker the heading can say anything. Without it the gate still finds the section the old
way and says once that it did.

**`kind` in a run file**, where a run writes one — `feature`, `errand`, `batch` or `epic`:

```json
{ "command": "ship", "kind": "feature" }
```

Only runs whose `prompt` is written in prose need it. Those are indistinguishable from a feature by
any reading of the file, and until now they were all read as errands — which meant a feature that
carried a hand-written prompt was never asked what its tests returned, which tree they ran on, or
what its mutation run found. The commands write this field themselves from now on; the line above is
for a run file you are editing by hand.

## Three things that start being said

- **A `source:` line written without its hash is named.** It used to match nothing at all, so an
  entry that named its source read exactly like one that named none, and `--record` never filled it
  in. A line pointing at a URL is counted separately and not judged — nothing here can fetch a page.
- **A run file nothing can parse is named**, instead of being skipped. So is a file in
  `docs/advice/` that no lens of `advise` writes.
- **A command declared in `project.yml` that starts nothing** — `test: make test` with no makefile —
  was already named as of 2.19.3, and is fatal at an `epic`'s gate.

## One thing that changes behaviour

The end-to-end command is now refused inside `/agent-kit:fix` as well as inside `/agent-kit:ship`.
A fix proves one change the way a feature does; walking the whole product belongs to whatever
integrates a batch. If your `fix` runs relied on that, run the end-to-end suite from your own
terminal or from CI.
