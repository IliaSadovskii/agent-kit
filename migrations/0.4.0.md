# Migrating to 0.4.0

0.4.0 turns the kit into a Claude Code plugin. There is no in-place update path from a vendored
install: the old `.agent-kit/scripts/kit-update.sh` fetched a payload that no longer exists. The
migration is manual, and short.

Your project keeps everything it owns. Only the kit's own files go away.

## 1. Install the plugin

```text
/plugin marketplace add IliaSadovskii/agent-kit
/plugin install agent-kit@agent-kit
```

To pin it for everyone working in the repository, commit this to `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "agent-kit": { "source": { "source": "github", "repo": "IliaSadovskii/agent-kit" } }
  },
  "enabledPlugins": { "agent-kit@agent-kit": true }
}
```

## 2. Remove the vendored kit

Everything below was owned by the kit and is now supplied by the plugin:

```bash
rm -rf .agent-kit/engine.md .agent-kit/workflows .agent-kit/skills .agent-kit/roles \
       .agent-kit/rules .agent-kit/scripts .agent-kit/catalog.txt .agent-kit/GUIDE.md \
       .agent-kit/NOTICE.md .agent-kit/kit.lock
rm -rf .claude/commands .claude/skills .claude/agents
```

**Keep `.agent-kit/project/`.** `manifest.yml` and `instructions.md` are yours, they are unchanged
in 0.4.0, and the plugin reads them exactly as before.

If you had put your own commands or skills under `.claude/`, move them aside before running the
second `rm` — the kit's wrappers were the only thing it owned there, but the directories are shared.

## 3. Clean up `CLAUDE.md` and the settings hook

The plugin injects its governance through its own SessionStart hook, so the managed block is dead
weight. Delete everything between `<!-- kit:managed:start -->` and `<!-- kit:managed:end -->`,
inclusive. Keep your own overrides below it.

Then remove the kit's hook from `.claude/settings.json` — the entry whose command points at
`.agent-kit/scripts/session-setup.sh`. If that was the only hook in the file, the whole `hooks`
object can go. Dependency setup still runs: the plugin's own hook calls your
`scripts/cloud-setup.sh`, which stays where it is.

## 4. Learn the new command list

Two things changed at once: the surviving commands are namespaced, and four commands are gone.

| Before | Now |
|---|---|
| `/ship`, `/fix`, `/debug`, `/docs`, `/riff` | `/agent-kit:ship`, `/agent-kit:fix`, `/agent-kit:debug`, `/agent-kit:docs`, `/agent-kit:riff` |
| `/go` | removed — run `/agent-kit:ship`, which bootstraps an unbootstrapped project itself |
| `/review` | removed — type `/code-review`, which is built into Claude Code |
| `/test` | removed — ask for tests in plain words |
| `/infra`, and the `infra-local` / `infra-cloud` skills | removed, with no replacement |

The subagents are `agent-kit:reviewer` and `agent-kit:tester`.

If you referenced the old names in your own docs, scripts, or scheduled tasks, find them with:

```bash
grep -rn '/\(go\|ship\|fix\|debug\|review\|test\|docs\|infra\|riff\)\b' --include='*.md' .
```

### If you used `/infra`

Nothing it generated is taken away: your `Dockerfile`, `docker-compose.yml`, CI, and
`docs/deployment.md` are files in your repository and stay exactly as they are. What you lose is the
guided workflow that produced and refreshed them. Provisioning was always interactive and
owner-driven, so from here it is an ordinary conversation with Claude rather than a pipeline.

Two manifest keys go with it. `infrastructure:` and `sources.deployment` are no longer read by
anything, so you can delete them from `.agent-kit/project/manifest.yml` — or keep
`sources.deployment` if you want the agent to know where your runbook lives, since skills still take
every documentation path from `sources`.

## What changed in behavior

Worth knowing, though nothing here needs action from you:

- `ship`'s review step now runs `/code-review` for correctness and the `reviewer` agent for whether
  the diff matches the approved design. The security step runs `/security-review`, or the
  `claude-security` plugin when you have it enabled.
- `ship` and `test` confirm changes against the running app with `/verify` when the change has a
  runnable surface.
- `brainstorming` explores the codebase with `Explore` agents and generates competing architectures
  before proposing a design, on features large enough to justify it.
- If you had edited a kit-owned file locally, that edit is gone with the vendored copy. The plugin
  cannot carry it. Move the change into `.agent-kit/project/instructions.md`, or send it upstream.
