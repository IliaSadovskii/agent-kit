# Migrating to 0.17.0

Three commands are gone from the list and nothing they did is gone with them. Each is now a skill
the surviving commands invoke, with the same procedure it always had.

Nothing in your project needs changing. This note exists so that a command you can no longer find
has an obvious answer.

## Where the three went

| Before | Now |
|---|---|
| `/agent-kit:debug <symptom>` | `/agent-kit:fix <symptom>` — when the task names a symptom rather than a change, `fix` runs the root-cause pass first, then continues through its own tail |
| `/agent-kit:address <pr>` | `/agent-kit:fix --pr <n>` — same run, same execution contract, reached through a flag |
| `/agent-kit:screens-riff <focus>` | `/agent-kit:riff <focus>` — a screen theme runs the screens pass, which still writes taken proposals onto the map as `idea` cards and turned-down ones as `rejected` memory |

A screen theme is a theme carrying a standalone `S<digits>` token — `S7`, alone or in a sentence —
or naming screens, the map, or the screens of a flow. `riff` is interactive, so a theme that could
go either way is asked about rather than guessed.

`/agent-kit:fix` widened to match: it is no longer only "the light path for a small change" but
*something is wrong — your words, a PR review, or an observed failure*. It still has no design gate;
a task that turns out to need one is still handed to `/agent-kit:ship`.

If you referenced the old names in your own documents, scripts, or scheduled tasks, find them with:

```bash
grep -rn '/agent-kit:\(debug\|address\|screens-riff\)' .
```

## What did not change

- The three skills' procedures are untouched. Absorbing an entry point is not a rewrite.
- `/agent-kit:docs` stays a command. It is absorbed into `blueprint --check` in a later release,
  when there is something to absorb it into.
- `/agent-kit:riff` stays a command. Its broad scope is unchanged; the screen theme is a second way
  in, not a replacement.
