# agent-kit

Плагин для Claude Code, который строит приложение по его описанию.

Продукт описывается один раз — что он делает, чего сознательно не делает, по каким правилам
собирается, — и дальше команды работают по этому описанию: починить баг, выкатить фичу, отработать
батч, собрать первую версию целиком. Описание — это то, что удерживает долгий автономный прогон в
рамках: гадать не приходится ни о чём, а каждое решение, принятое без вас, записано там, где вы его
увидите.

> **Переписывается.** Сейчас работают `/agent-kit:blueprint` и `/agent-kit:ship`, остальные
> объявлены и ничего не делают. Последняя полная версия — тег `v0.17.0`.

## Установка

```text
/plugin marketplace add IliaSadovskii/agent-kit
/plugin install agent-kit@agent-kit
```

Закрепить за репозиторием — в `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "agent-kit": { "source": { "source": "github", "repo": "IliaSadovskii/agent-kit" } }
  },
  "enabledPlugins": { "agent-kit@agent-kit": true }
}
```

Нужны `git` и `gh` — второй для пул-реквестов.

## Команды

### `/agent-kit:blueprint [что добавить или переосмыслить] [--check]`

Описывает проект: чем он является и чем сознательно не является, стек и правила, по которым идёт
сборка, акторы, сущности, действия, экраны, интеграции, сценарии, границы MVP. Опрашивает вас, пишет
`docs/knowledge/`, коммитит каждый слот по мере готовности — можно остановиться в любой момент и
продолжить потом.

| Форма | Что делает |
|---|---|
| `blueprint` | продолжает с места остановки: пустое, устаревшее, помеченное прошлым прогоном |
| `blueprint "переработать карту"` | забирает в нужные слоты то, что вы придумали уже после |
| `blueprint --check` | запущен руками: где стоит проект — построено, запланировано, открытые вопросы, ждущие ответа допущения. Запущен другой командой: молчит, если всё чисто |

На проекте с готовым кодом сначала читает код и приносит черновик на исправление. Приложение не
запускает, ваши документы не переписывает — ссылается на них по секциям.

### `/agent-kit:ship [ключ действия или что построить]`

Одна фича до пул-реквеста: дизайн по записи, сборка, проверка, ревью, PR.

Спрашивает только там, где развилку дорого откатывать: форма хранимых данных, публичный контракт,
права, деньги. Всё остальное решает сам и записывает в PR. Тесты берутся из строк самой записи и пишутся до кода.
Один проход ревью сверяет дифф с записью; проход по безопасности включается, если дифф трогает
авторизацию, недоверенный ввод, деньги, файлы, миграции или внешние вызовы.

Работает и без blueprint — от текста задачи, один раз сказав, чем это платится.

### `/agent-kit:fix [что не так] [--pr <n>]` — не написана

Что-то сломано и это небольшое: ваше описание, замеченный сбой или круг правок по комментариям к
открытому пул-реквесту.

### `/agent-kit:sprint [тема]` — не написана

Батч фич, отбрифованный за один заход, дальше собирается автономно и сдаётся одним мержабельным
пул-реквестом.

### `/agent-kit:mvp [объём]` — не написана

От blueprint до работающего прототипа: собирает батчи по границам MVP и гоняет их, пока все сценарии
не пройдут на живом приложении.

### `/agent-kit:audit <линза> [область]` — спроектирована, не написана

Читает существующий код, сравнивает с blueprint и пишет список работ — тесты, безопасность,
производительность, долг, готовность к проду. Ничего не меняет. Для кода, за написанием которого
никто не следил: подхваченный проект или батч, который автономный прогон выкатил за ночь.

## Цикл

**Знать → строить → сверять → строить.** Входить можно с любой точки:

| Что есть | Порядок |
|---|---|
| только идея | `blueprint` → `mvp` → `audit` → `sprint` |
| полукаркас | `blueprint` → `audit` → `ship` / `sprint` |
| готовое приложение | `blueprint` → `audit` → `sprint` → `fix` |

Все команды работают при отсутствующем знании, кроме `mvp` — он отказывается, потому что без границ
и сценариев у него нет условия остановки. Начинать с `blueprint` не обязательно: починить баг —
нормальная первая команда.

## Где что лежит

| Путь | Что | В гите |
|---|---|---|
| `docs/knowledge/` | описание проекта, по файлу на слот | да |
| `.agent-kit/project.yml` | язык, команды проекта, вердикт по каждому слоту | да |
| `.agent-kit/runs/<slug>/` | состояние прогона и его лог событий | нет |

Кит работает на ветках, никогда не мержит пул-реквесты и не пишет прозу нигде, кроме
`docs/knowledge/`.

## Разработка самого кита

`scripts/validate.sh` проверяет раскладку, манифесты, версии и внутренние ссылки; CI гоняет его же.
`scripts/measure.py <проект>` считает, во что обошлись прогоны — по сессиям или по веткам. Дизайн —
в [docs/design/](docs/design/), релизы — в [CHANGELOG.md](CHANGELOG.md).
