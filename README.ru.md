# agent-kit

Плагин для Claude Code. Вы один раз описываете проект, дальше команды строят по этому описанию.

Описание лежит в `docs/knowledge/`: акторы, сущности, действия, экраны, интеграции, сценарии, стек и
то, что входит в первую версию. Пишет его `blueprint`. Читают и превращают в код `ship`, `fix`,
`sprint` и `mvp`. Сверяет код с описанием `audit`.

> Переписывается. Сейчас работают `blueprint`, `ship` и `audit`, остальные объявлены и ничего не
> делают. Последняя полная версия — тег `v0.17.0`.

## Установка

```text
/plugin marketplace add IliaSadovskii/agent-kit
/plugin install agent-kit@agent-kit
```

На весь репозиторий — в `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "agent-kit": { "source": { "source": "github", "repo": "IliaSadovskii/agent-kit" } }
  },
  "enabledPlugins": { "agent-kit@agent-kit": true }
}
```

Нужен `git`, для пул-реквестов ещё `gh`.

## Команды

### `blueprint`

Опрашивает вас и пишет описание. Каждый слот коммитится по готовности, так что можно остановиться и
вернуться позже.

- `blueprint` — продолжить с пустого, устаревшего или помеченного прошлым прогоном
- `blueprint "переработать карту"` — добавить или переосмыслить одну вещь
- `blueprint --check` — где стоит проект: построено, запланировано, открытые вопросы, допущения,
  которые ждут вашего ответа

На готовом коде сначала читает код и приносит черновик на исправление. Приложение не запускает, ваши
документы не переписывает — ссылается на них.

### `ship <ключ действия | что построить>`

Одна фича, один пул-реквест. Проектирует по записи, собирает, тестирует, ревьюит, открывает PR.

Спрашивает только про развилки, которые дорого откатывать: форма хранимых данных, публичные
контракты, права, деньги. Тесты берутся из записи и пишутся до кода. В PR перечислено, что принято
допущением и что доказано.

Работает и без blueprint — от текста задачи.

### `fix <что не так>` · `fix --pr <n>` — не написана

Небольшая правка: ваше описание, замеченный сбой или круг комментариев к PR.

### `sprint <тема>`

Несколько фич, отбрифованных за один заход, дальше собираются без вас — каждая своей видимой
сессией, по очереди, цепочкой, и вся пачка приходит одним мержабельным пул-реквестом. Рядом стоит
управляющая сессия: расскажет, как идут дела, и примет *паузу*, *пропуск* и *стоп*.

### `mvp` — не написана

Строит всё, что входит в границы MVP, пока сценарии не пройдут на запущенном приложении.

### `audit [линза] [область]`

Сверяет существующий код с тем, что описание объявляет верным, и пишет список работ.
Ничего не меняет.

| Линза | Что проверяет |
|---|---|
| `tests` | что код обещает, а тестами не проверено — и где тест есть, но проверяет не то |
| `deps` | какие пакеты устарели или дырявые, и опасно ли это конкретно здесь |
| `scenarios` | проходит ли пользователь весь путь до конца и на каком шаге он ломается |
| `security` | кто может увидеть или сделать то, чего не должен |
| `performance` | где код тормозит по понятной причине: лишние запросы, выборки без границ, работа в цикле |
| `conventions` | где код разошёлся с правилами, которые вы сами для него написали |

- `audit` — все линзы, от дешёвых к дорогим
- `audit тесты` — одна линза; `тесты` и `tests` это одно и то же
- `audit тесты модерация` — суженная областью
- `audit "почему модерация тормозит"` — скажет, какую линзу понял, и запустит

Любой прогон заодно ищет в коде поверхности, которых нет в описании, и наоборот. У каждой находки
стоит файл и строка, которые её доказывают, — вердикт проверяется за десять секунд. Список лежит
в `docs/audits/<линза>.md`, разбит на партии по одному прогону `ship`; помеченный отклонённым пункт
следующие прогоны не поднимают.

## Порядок работы

| Что есть | Порядок |
|---|---|
| только идея | `blueprint` → `mvp` → `audit` → `sprint` |
| полукаркас | `blueprint` → `audit` → `ship` / `sprint` |
| готовое приложение | `blueprint` → `audit` → `sprint` → `fix` |

`audit` нужен там, где за написанием кода никто не следил: доставшийся проект или батч, приехавший
за ночь. После `ship` он лишний.

Blueprint обязателен только для `mvp`. Остальные работают без него.

## Файлы

| Путь | Что | В гите |
|---|---|---|
| `docs/knowledge/` | описание, по файлу на слот | да |
| `.agent-kit/project.yml` | язык, команды проекта, вердикт по каждому слоту | да |
| `.agent-kit/runs/<slug>/` | состояние прогона и лог событий | нет |

Кит работает на ветках и никогда не мержит пул-реквесты.

## Разработка кита

`scripts/validate.sh` проверяет раскладку, манифесты, версии и внутренние ссылки; CI гоняет его же.
`scripts/measure.py <проект>` считает стоимость прогонов — по сессиям или по веткам. Дизайн —
в [docs/design/](docs/design/), релизы — в [CHANGELOG.md](CHANGELOG.md).
