# Step gate — Implementation Plan

**Goal:** close a pipeline step with a gate that runs the criteria and writes the verdict, so the
agent can ask but never declare.
**Architecture:** one stdlib-only model (`kit_gate.py`) shared by a CLI (`gate.py`) and three hooks,
reading pipeline definitions from `pipelines.default.yml` and writing run state to
`.agent-kit/runs/<slug>.yml`, which two `PreToolUse` hooks keep out of the agent's reach.
**Tech stack:** Python 3 standard library only, `kit_yaml` for reading and writing, bash wrappers for
the hooks, `scripts/validate.sh` as the whole declared suite.

Design: `docs/specs/2026-07-31-step-gate-design.md`.

## Global constraints

- Nothing under `plugins/agent-kit/` imports a third-party module; `validate.sh` parses every `.py`
  to hold the line.
- Code, paths, commit messages and documents under `docs/` are English. The pull request description
  is Russian.
- `VERSION`, `plugin.json` and `marketplace.json` stay at 0.16.0. `CHANGELOG.md`'s `## 0.17.0`
  section is appended to; `migrations/0.17.0.md` gets a note.
- Editing `docs/developing.md` requires updating the `rev` bound to that section in
  `.agent-kit/knowledge/contract.yml`; the failure prints the new hash.
- Every shell command a project's files supply runs through `guard.refusal()`. Every path the kit
  owns by name goes through `kit_knowledge.kit_owned()`.
- Exit codes: `0` clean, `1` findings (a check failed), `2` structural (unreadable file, malformed
  declaration, unsupported construct).

### Task 1: The model — `kit_gate.py`

**Files:** create `plugins/agent-kit/scripts/kit_gate.py`.
**Interfaces:** `GateError(message, structural)`; `load_pipelines(plugin_root)` →
`{name: [Step, …]}`; `Step` with `name`, `requires`, `checks`, `max_attempts`, `on_exhausted`,
`optional`, `skippable_when`; `state_path(root, branch)`; `load_state(root, branch)` → dict or
`None`; `write_state(root, state)`; `run_check(root, check)` → `Evidence`; `is_terminal(step_state)`;
`unsettled(state, steps)`.
**Behavior:** reads and validates a definition file, names an unsupported check kind or
`on_exhausted` value and raises structurally, resolves and atomically writes run state through
`kit_owned`, executes the three supported check kinds, and answers which steps are still open.
**Verification:** unit tests in `tests/test_gate.py` over fixture pipelines; a malformed definition
raises `GateError(structural=True)`.

### Task 2: The CLI — `gate.py`

**Files:** create `plugins/agent-kit/scripts/gate.py`.
**Interfaces:** `gate.py step start <Name> [--pipeline <name>]`,
`gate.py step settle <Name> [--evidence <text>]`, `gate.py step skip <Name> --reason <name>`,
`gate.py state`.
**Behavior:** `start` refuses a step whose predecessors lack a terminal verdict and prints the
closing criteria as a list; `settle` runs the checks and writes the verdict, or names the failing
check with its exit code and output tail and exits 1; `skip` accepts only a declared condition;
`state` prints a capped human summary and nothing at all when there is no run.
**Verification:** `tests/test_gate.py` drives the CLI as a subprocess over fixtures and asserts exit
codes, stdout, and the resulting state file.

### Task 3: The guards — `guard.py`, `write-guard.*`, `hooks.json`

**Files:** modify `plugins/agent-kit/scripts/guard.py`,
`plugins/agent-kit/scripts/blueprint_check.py`, `plugins/agent-kit/hooks/hooks.json`; create
`plugins/agent-kit/scripts/write-guard.py` and `write-guard.sh`.
**Interfaces:** `guard.Refusal(decision, reason)`; `guard.refusal(command)` → `Refusal | None`;
`guard.DENY`, `guard.ASK`.
**Behavior:** a command naming `.agent-kit/runs` that is not a `gate.py` invocation is denied; the
never-rules keep asking; the new hook denies a `Write` or `Edit` whose path carries the
`.agent-kit/runs` segment; both fail open on unreadable input.
**Verification:** `tests/test_guard.py` for the decision, `tests/test_gate_hooks.py` for the hook
protocol, including the malformed-event path.

### Task 4: `Stop` and `SessionStart` on run state

**Files:** rewrite `plugins/agent-kit/scripts/stop-guard.py`, modify `stop-guard.sh` and
`session-start.sh`.
**Behavior:** `Stop` blocks while the run is `open`, owned by the stopping session (or unowned), and
a declared step lacks a terminal verdict; it is silent with no state file, on a foreign branch, for
another session's run, on a finished or blocked run, and on anything unreadable. `SessionStart`
appends `gate.py state` after `engine.md` and never fails the hook.
**Verification:** `tests/test_gate_hooks.py` — one case per silence condition and one for the block,
each a crafted event on stdin.

### Task 5: The pipeline definitions and the Run log contract

**Files:** create `plugins/agent-kit/pipelines.default.yml`; modify
`skills/{ship,fix,sprint,writing-plans}/SKILL.md`, `.gitignore`.
**Behavior:** `ship` and `fix` are described step by step; ship's Run log section tells the agent to
call the gate and drops the `**Steps:**` header; `writing-plans` drops it from the contract it
documents; `sprint`'s completion check reads the child's run state and its launch exports
`AGENT_KIT_SESSION_ID`.
**Verification:** `tests/test_gate.py` loads the shipped file and asserts every step validates;
`scripts/validate.sh`'s frontmatter and reference checks stay green.

### Task 6: The suite — tests, mutation harness, `validate.sh`

**Files:** create `tests/test_gate.py`, `tests/test_gate_hooks.py`, `tests/mutate_gate.py`,
`tests/fixtures/gate-*/`; modify `tests/test_guard.py`, `scripts/validate.sh`.
**Behavior:** the property-based layer explores start/settle/skip sequences against the invariants;
the mutation harness applies a deterministic set of AST mutations to `kit_gate.py` and requires each
to be killed by `tests/test_gate.py`; `validate.sh` gains the layout entry, the tightened hook-output
cap, and the mutation step.
**Verification:** `scripts/validate.sh` green, mutation survivors zero or explicitly listed with a
reason.

### Task 7: Release notes

**Files:** modify `CHANGELOG.md`, `migrations/0.17.0.md`, `.agent-kit/knowledge/contract.yml` if
`docs/developing.md` changes.
**Behavior:** the 0.17.0 section gains this feature's bullets; the migration note says what now
closes a step for a project already using the kit.
**Verification:** `scripts/validate.sh`'s CHANGELOG and knowledge checks.

## Run log

**Branch:** claude/step-gate
**Steps:** Build, Test, Review, Security, PR, Docs

- Task/Ideate skipped: `--brief` supplies the chosen, scoped task.
- `stack-playbook` freshness: nothing to refresh — this repository has no dependency manifest to
  fingerprint, and `manifest.sources.coding_standards` points at `docs/developing.md`, a hand-written
  guide rather than a generated playbook.
- The session is not in an auto permission mode banner-wise; it is a headless `-p` run, which is what
  autonomous mode is for.
- Deviation: `pipelines.default.yml` describes `ship` and `fix`, not `sprint`. The sketch's scope
  line names all three. The orchestrator checks the working tree out onto each child's branch as it
  goes, and run state is keyed by branch, so an orchestrator run would be invisible to its own `Stop`
  hook for most of a sprint and visible again between features. An intermittent guard reads as
  assurance and is not. `sprint` still gets the two changes the sketch's settled decisions name — its
  completion check moves onto run state, and it exports the child's session id.
- Expansion, per `upstream.md`: run state records the session that opened the run, and `Stop` holds
  only that session (or any session when the field is unset). Without it the new mechanism inherits
  the shared-working-tree defect it exists to fix. The id comes from `AGENT_KIT_SESSION_ID`, which
  `sprint` now exports beside `--session-id`, falling back to `CLAUDE_CODE_SESSION_ID` — verified in
  this session to equal the session id the hook payload carries.
- Decision: `pipelines.default.yml` is written in block-style lists. `requires: [Design]` is a flow
  collection, which the kit's YAML subset deliberately does not read, and widening a reader four
  scripts share for cosmetics is a change to the wrong file. The reader names the construct and the
  line, so an owner editing the file in stage 4 is told exactly what to write.
- Autonomous default: the gate writes `.agent-kit/runs/.gitignore` containing `*` when it creates
  the directory. Without it `git: tree_clean` — the PR step's own check — could never pass in a
  project that had not yet been told to ignore the path, and the project's `.gitignore` is the
  project's file to edit, not the kit's.
- step Build — done
- Test step: the `agent-kit:tester` agent wrote `tests/test_gate.py` (55 tests: parser, checks
  against a real git repository and a real bare remote, the CLI as a subprocess, the shipped
  definition against the skills' prose, and a property-based walk over eight fixed seeds) and
  `tests/test_gate_hooks.py` (26 tests: crafted JSON into each hook, covering allow, deny and the
  malformed-input fail-open path). It skipped end-to-end (the plugin runs from an installed copy),
  performance (the only budget is a 1,800-second timeout), and a real two-process race on run state
  (`os.replace` is atomic and last-writer-wins is the design; a timing test would be the flake).
- Three defects the tester found, all fixed here rather than in the tests:
  - the Bash guard exempted any command naming `gate.py`, so `gate.py state > .agent-kit/runs/x.yml`
    was allowed to clobber run state. The exemption is gone — the gate derives its path from the
    branch and never names the directory, so it never needed one.
  - `run: true` reads as a boolean and was reported as "needs a non-empty value". It now says what
    it actually read.
  - `gate.py`'s exit codes disagreed with its own docstring. Settled as: 1 is the gate saying no
    (a check failed, or this run's state refuses the request), 2 is the gate unable to answer (the
    invocation, the declaration, or the state).
- step Test — verified: scripts/validate.sh → 0 (61 gate tests, 26 hook tests, 117 mutants)
- Autonomous default: the mutation pass runs from `scripts/validate.sh` behind `KIT_MUTATE=1`, and
  `.github/workflows/ci.yml` sets it. Seven minutes against fifteen seconds for the rest of that
  file; a pre-release check nobody waits for is a check nobody runs.
- Deviation: the fixture pipelines are strings inside `tests/test_gate.py` rather than
  `tests/fixtures/gate-*/` as the spec's verification section says. Two of them declare a check that
  fails on purpose, and a definition read a screen away from the assertion about it is one nobody
  re-reads.
- step Review — attested: agent-kit:reviewer against the sketch, upstream.md, the spec, the plan
  and docs/developing.md. Verdict: the feature that was approved, nothing from the Out list built,
  all nine settled decisions implemented literally. Eighteen findings; the majors are folded in

- step Security — attested: /security-review over the branch diff. Every finding was reproduced
  before it was fixed, and the list plus the two deliberate non-fixes are in the spec under "What
  the security pass changed". The three that mattered most: the atomic write's `.kit-new` sibling
  was not a kit-owned path, so a symlink shipped in a pull request would have been written through;
  `_git` returned the same empty string for "nothing to report" and "git did not answer", so an
  index.lock made the PR step's two checks pass; and `kit_yaml.dump` raising on a value it cannot
  render meant the attempt was never recorded, `max_attempts` was never reached and the `Stop` hook
  held for ever — the exact deadlock the sketch forbids.
- Addition beyond the sketch: `gate.py run reset --reason "<why>"`. Two real paths had no way out —
  `sprint`'s "one informed retry" relaunches onto a branch still carrying the previous attempt's
  state, and an abandoned run nudges every turn with only a human able to delete the file. It closes
  nothing and grants nothing the design did not already allow, since no state file already means no
  run. Recorded here rather than assumed: it is a command the sketch did not name.
- Deviation: `requires:` is no longer re-checked at `step start`. The parser already establishes
  that it names an earlier step, and every earlier step must be terminal for the step to open, so
  the second check could not fire. It stays in the definition file, validated, as the dependency
  stated rather than inferred.
