# The 5 August audit, and what is left to do

Written for a session that starts fresh with this file as its only context. It says what an audit of
the whole kit found, what was fixed the same day, what was deliberately not fixed, and what is still
proposed but unbuilt.

**Read the proposals as arguments, not as instructions.** They were written at the end of a long
session by the same person who built the thing being judged. Check each one against the files as
they are now, say where you disagree, and **ask the owner before you start** — with the disagreement
in front of them, not after the work.

## Where the kit stands

Version 1 is a rewrite from scratch. The line before it ended at 0.17.0, where one feature cost 27M
tokens and the diagnosis was that "nearly every expensive mechanism existed to insure the kit against
its own autonomy" — four rules existed only to serve other rules. The reasoning is in
[kit-v1.md](kit-v1.md); the measurements in [0.17.0-measurements.md](0.17.0-measurements.md).

On 5 August 2026 the kit went from 0.26.0 to 0.39.0 in one session — thirteen releases, each adding
a mechanism in answer to a defect seen in a live run on a real project (`/projects/metsomeone`).
That is a healthy source of growth, and also the thing to watch: the same day, `ship/SKILL.md` grew
52%, from 12.9 KB to 20 KB.

Measured against what the rewrite escaped: plugin markdown −25%, `ship`'s reading set −33% (13.6k
tokens → 9.1k), `ship/SKILL.md` −39% (32 KB → 20 KB). Six commands work; `mvp` is a stub.

## What the audit found, and what was done

All of these were reproduced before being fixed, and all fixes are in 0.39.0 unless said otherwise.

**A crash that took every command down.** `check.py` moved an entry to `built` after its pull
request merged, rewrote the document, and then died in the next check with `ValueError: substring
not found` — the parsed entries still pointed at the replaced text. It fired on the day a feature
landed, and no test covered that branch. Fixed by reparsing after the write; a regression test now
runs against a fake `gh`.

**`next` was writing to the knowledge it claims never to touch.** It ran the check without
`--offline`, which asks GitHub about `building` entries and rewrites their state lines — leaving
uncommitted changes, which its own ladder calls the most urgent finding. Fixed.

**Records with only one side.** Each of these had a reader and no writer, or the reverse:

| Record | What it is for | What was done |
|---|---|---|
| `waiting_on` | the fork a run is stopped on — the only route by which a night's question reaches a phone | `ship` now writes it |
| `waiting_since` | how long it has been stopped | deleted; nothing read it |
| `agent-kit:scenario` | a test declaring which scenario it walks | `ship` now writes it; without a writer, "no scenario is covered" was true by construction |
| `commands.types` | the project's type checker | the slot exists now; `ship` had been told to run it since 28 July |
| `commands.run` | what starts the application | named in the step that starts the app |
| `PreToolUse` guard | a hook `blueprint` expected to stop a push | the sentence is gone — see *Decided against* |

The causes were four different ones, and they are worth remembering because they will recur:
a template and an instruction written in the same commit but never checked against each other
(`waiting_*`); an instruction referring to a schema nobody verified (`commands.*`); a mechanism
built from the wrong end — the meter before the source (`agent-kit:scenario`); and a leftover from
the previous version (the guard).

**Rules describing things that had changed underneath them.** `blueprint` promised a guard the
payload does not contain, kept a `--hash` path that contradicts `--record`, and claimed the check
verifies a status against its entity — which the program's own closing line denies. The debt
template seeded a phantom item: its own example was an open box outside a fenced block, so every
fresh project started one item in debt. `close.md` claimed to be the only thing that ticks an audit
box, which stopped being true when `next` gained that right. All corrected.

**The unmet list is no longer truncated.** It was cut to ten for context; `ship` is told to read the
marked test for the entry it is about to touch, and a trimmed list could hide exactly that one.

**`run.log` stopped duplicating the run file.** Assumptions, answers and review findings have had
fields of their own since 0.36.0.

## Decided against, deliberately

- **The hooks stay unbuilt.** `kit-v1.md` argues for two (`PreToolUse` refusing merges and pushes to
  the default branch; `PreCompact` reminding a run to re-read its file). Neither exists, and the
  rule now reads as instruction rather than machinery. The reason it matters: a rule that expects to
  be stopped by something that does not exist is worse than the same rule alone, because the run
  believes it is covered. Either the hook exists or no text refers to it.
- **`waiting_since` is not coming back.** It could tell `next` that a question has been waiting three
  hours rather than three minutes. Judged not worth another field.
- **The marks keep their names.** `agent-kit:unmet` and `agent-kit:scenario` read like the slash
  commands `/agent-kit:ship` — the owner mistook one for a command mid-session. Renaming was offered
  (`agent-kit-unmet`, `kit:unmet`) and declined; the documentation says plainly that they are
  comments in a test.

## What is proposed and not built

The audit's real finding is not any single defect: it is that **a `ship` run must hold 22 mechanisms
at once**. That is width of attention, not file size, and it is the thing that killed 0.17.0. Below
is the plan as it stood when the session ended. Judge it before you execute it.

### 1. Six bookkeeping rules become one table

Today a run learns six separate rules about where a finding goes, spread over three sections and
written as prose: the `agent-kit:unmet` mark, an `[assumed …]` block, a `[found …]` block, a line in
`docs/technical_debt.md`, `deviations`, and `notes`.

They are one idea — *what you found → where it goes → who reads it* — and they want to be one table
of about seven rows. Roughly 50 lines of prose become 10, and six things to remember become one.

**Check before doing it:** that no row loses a distinction the prose was carrying. `[assumed]` and
`deviations` are close enough to be worth reading twice; so are "debt" and "a promise the product
does not keep".

### 2. The form of the mark leaves `ship`

Thirty-nine lines about the `unmet` mark — the code example, `xfail` versus `todo`, "only for code
that was there before you" — open the file, before it has said what the command does. The rule stays
in `ship` in three lines; the form moves to `references/unmet.md`, which is read once in a project's
life.

**Check before doing it:** an earlier version of this proposal was rejected on the grounds that
hiding a *rule* one level down is how 0.17.0's rules stopped being read. Hiding the *form* is a
different claim. Decide whether you believe it.

### 3. The debt mechanics leave `ship`

Fifteen lines on delete-don't-tick, "half an item is worse than none", `closed_debt`. What stays:
deferred work is a line in the ledger and in `deferred`; finished work is deleted and named in
`closed_debt`. The rest to a reference.

### 4. `run.log` leaves the agent's hands entirely

It is already cut to two events. `kit-v1.md` says the log is "written by the driver and the hooks,
never by the agent" — so `ship` has contradicted the design since it was written. The driver keeps
its own log for a batch.

**Check before doing it:** whether anything reads a child's log. `window.md` mentions "the tail of
`run.log`" for *when* things happened.

### 5. Three rules move from prose into the program

These hold only if the run remembers them, and all three are trivial to check mechanically:

- an open critical or major finding in `review` is not `step: done`;
- `suite` is not empty at `done`;
- a mark left `unmet` with nothing in `deviations`.

`check.py` already reads run files (it names unknown fields). The rule stays in the text as one
line, but its enforcement stops depending on memory — the same reason the knowledge check became a
program rather than an instruction.

**Check before doing it:** where the finding should surface. These are defects in a run, not in the
project's knowledge, so they may not belong in the same report as a stale source hash.

### Expected result

22 mechanisms → about 14, `ship/SKILL.md` 20 KB → about 15. **Not proposed:** splitting `ship` into
one file per step. A run would read all four anyway, in four calls, and lose the link between how it
designed and what it verifies.

## Standing limits worth keeping

- **`ship`'s reading set has a ceiling.** 9.1k tokens today against 13.6k in 0.17.0. If a change
  pushes it past roughly 12k, delete a mechanism rather than trimming an explanation — explanations
  are what make a rule executable, and cutting them is what left 0.17.0 with laws and no reasons.
- **Every new mechanism arrives with three answers**: who writes it, who reads it, and what becomes
  impossible without it. No third answer, no mechanism. Half of today's defects were mechanisms
  missing one of the first two.
- **`validate.sh` should grow a check for exactly that** — for every field in `templates/run.json`,
  find a writer and a reader among the plugin's own files. It would have caught `waiting_on`,
  `waiting_since`, `commands.run` and `commands.types` on the day each was written. This is
  unbuilt and is the cheapest thing on this page.

## Two things the kit still cannot do

- **Nobody writes the scenarios' end-to-end tests.** The lens wants them and does not write them
  (`audit/references/scenarios.md`), `ship` tests an entry's lines rather than a scenario, and
  `mvp` — which was meant to close this — is a stub. On the live project: eleven scenarios
  described, none covered.
- **`fix` has never run**, and `ship` has only ever run inside a sprint. A mechanism that has not
  met a live run is a hypothesis.
