# What an independent read of 2026-08-11 found, and what was done about it

Eleven releases went out in one day, 1.3.0 to 2.4.1, almost none of it exercised on a live project.
[2026-08-11-review-brief.md](2026-08-11-review-brief.md) asked a pass that had taken no part in that
reasoning to find where it was wrong. This is what came back, what the owner decided, and the two
places where the finding itself was wrong.

Twenty-one findings, twenty acted on. Everything below was checked against `/projects/beeplish` —
the one real project the kit has run on — rather than against the reasoning that produced it.

## What the live project settled

Reading is cheap and it moved four verdicts, so it is worth saying which facts came from where.

- **All 38 `ship` runs on beeplish carried `deliver: "branch"`.** They stop after the review, so
  steps 4 to 7 of Deliver have never run once. The state line that was said to dirty the tree is on
  a road nobody has driven; the finding stands and its cost does not.
- **The brief loses nothing, and the question was never about that.** Measured across all 52
  entries: 175 references named and pulled, none missed. A record is glued in when the entry names
  it and the record exists — always. What a brief cannot do is pull a record that was never
  written, and the only open question was whether it should *warn* about the name. Printing every
  backticked name the knowledge does not define named 22 innocents in one entry — statuses, columns,
  error codes. Held to the rule `check_references` already uses — a key is a declared actor's, or a
  screen — it names nothing false across all 52 entries. That is the rule now, and the residue is a
  warning that is missing for one class of hole, not a hole in what a run receives.
- **The audit-tick check fires 35 times on beeplish**, every one of them a box ticked before the
  rule existed, and 3 of the 35 are the lens's own `declined:` rows, which no pull request will
  ever close. It also overstated its own cost: `sprint` reads the unticked half, so an unsigned
  tick costs it nothing. What it really costs is the ability to check a tick, and a ticked item
  leaves every list for ever.
- **`docs/runs/<slug>.json` has never been written by the session that owns it.** The only one in
  existence covers eleven batches, was assembled by hand afterwards, and says so in its own header.

## The size question, measured rather than argued

The brief worried about `blueprint` growing 42% in a day. It was watching the wrong file.

| reading set | v1.3.0 | before this work | after |
|---|---|---|---|
| `ship` — SKILL.md, four rules, the run template | 40 588 | 49 487 | 49 842 |

`ship` grew 22% on 2026-08-11 while nobody was counting, and it is larger than `blueprint`'s 11.6k
tokens and read far more often.

Moving the batch chapters out of `rules/pull-requests.md` took 2 104 characters off it. The `manual`
field and two new rows in `ship` put them back. **The set did not shrink, and saying so is the
point**: the day's work bought a mechanism and paid for it in the same currency, which is a trade to
make deliberately rather than to discover later.

The metric in `CLAUDE.md` changed with it. Bytes are not what the outside work measures — IFScale
and ManyIFEval measure the number of instructions — and neither of the two ceilings this kit quoted
has a measurement behind it. What is watched now is how many norms meet at a command's hottest fork.

**The hottest fork is not where the brief thought.** It guessed `Deliver` (7 steps) and
`The interview` (31 norms). Both are sequential: a run holds one step, then the next. The worst
place is `ship`'s *the entry promises one thing and the code does another* — 14 norms out of six
files, all true at once, in the middle of a build, with no gate in front of it.

## Two findings that were wrong

Worth recording, because a review is judged on these as much as on the rest.

- **Links from the plugin to `docs/design/`** were reported as broken outside this repository. They
  are not: `.claude-plugin/marketplace.json` sits at the root, so the plugin installs with the whole
  repository and `docs/` travels with it.
- **Known remnant №1 — "delete step 6 of `ship`"** — rests on a premise that does not hold. A
  standalone `/agent-kit:ship` has no closing session, and `--sync` only ever moves
  `building → built`. Delete the step and a lone feature's entry stays `planned` for ever, which is
  known remnant №6 arriving from the other side. The step moved to just after the pull request is
  opened, with a commit, because the number does not exist before then.

Known remnant №4 — "move the unmet rule into the reviewer" — was struck out for a different reason:
the rule is already in `agents/reviewer.md`, and `ship` cannot lose it, because the reviewer is not
run at all on a diff that touches no product code.

## Mechanisms without four answers

The kit's rule is that every mechanism arrives with a writer, a reader, somebody allowed to close
it, and something that becomes impossible without it. Six of the day's mechanisms were missing the
third answer, and one was missing a channel entirely.

- **`handoff`** — nothing ever emptied it. The driver read "not empty" as "the note has landed", so
  every handoff after the first would fire on the next quiet minute and pass on a stale note; and
  the stop hook, which is silent while a note stands, went silent for the rest of the run. The
  incoming session empties it now, and the driver compares against the note it asked about.
- **`wait`** — removed. The window may not write into a run file, no child's session is alive
  between batches, and nothing anywhere put an answer into `answers`. Every `wait` could only run
  out its hours and arrive where the run would have arrived without it.
- **`manual`** — the section of a pull request the owner is obliged to act on had no field behind
  it. The closing session was told to merge lists that did not exist and `accept` was told to read
  records while also being told never to read prose. It is a field now: what, where, `proof`, `when`.
- **`agent-kit:unmet`** — three files named three different closers, and the one that can actually
  do it, `ship`, was never told. It has a row in its own table now.
- **A part's `walked:` / `derived` mark** — two readers were told to use a count nothing produced.
  `check.py` counts it, and the mark is English inside translated prose like every other mark here.
- **`docs/runs/<slug>.json`** — no check that a closed batch left one. `run_defects` asks now, and
  the driver calls `run_defects` itself, so forgetting is not enough to lose the measurement.

## Checks that were silent on input they could not read

- A knowledge file with no template in the kit slipped **three** checks at once — fields, shape and
  verdict — and the silence read as a clean file. The product template itself invites one
  (`endpoints.md` for an API, `commands.md` for a CLI), so this is a road the kit points at and has
  not paved. It is named now; the templates are still missing.
- `--brief` dropped every name it could not resolve while its own docstring promised the opposite.
- The `gh`-shaped hole — `sync_states` and `pull_requests` return empty when `gh` is absent,
  unauthenticated or switched off, and the output is then indistinguishable from "no open pull
  requests" — was reported and **deliberately left**: the owner's machines have a working `gh`.
  It is the third appearance of this class and it will be the next one.

## The guard had no expiry

`hooks/guard.py` arms on any run file that has not reached a terminal step, with no bound. One
abandoned run therefore disabled merging for every session in that project — the owner's own
included — until somebody edited JSON by hand. A run file untouched for a day no longer counts.

## Weighed and deliberately not done

Nothing here is a loose end. Each was put to the owner with its cost and declined, and each is
written down so the next pass does not spend the same hour proposing it again.

1. **A warning when an entry names an entity nobody wrote.** Nothing is lost from a brief — the
   record does not exist to be lost, and 175 references across 52 entries were pulled with none
   missed. What is missing is only the warning, and only for entities: a bare `learning_node` and a
   bare `in_progress` are the same string to a program, where `screen.x` and `user.y` are not.
   Closing it means marking references the way every other machine value here is marked
   (`entity:learning_node`) — a rule for everyone who writes knowledge, and every existing entry
   rewritten by hand, because the rewrite hits the same ambiguity. Declined: zero cases on the one
   live project, and the cascade rule in `rules/knowledge-writing.md` is what keeps it that way.
2. **Making a `walked:` date harder to fake.** No program can tell whether a conversation happened,
   any more than it can tell whether an application was really opened. Printing the dates rather
   than the count would at least make *six parts walked today* visible; declined for the line it
   adds to every check.
3. **Templates for `endpoints.md` and `commands.md`.** `product.md` offers both and the kit ships
   neither, so such a file is unchecked — which the check now says out loud. Writing them means
   deciding what fields such a record has, and that is worth doing on a real API project rather
   than on paper.
4. **A `migrations/` note for this release.** It adds three things an existing project does not
   have — the parts section and its marks, the `manual` field, and the record a closing batch owes
   — and `docs/runs/` on beeplish holds one hand-written file for eleven batches in a shape nothing
   reconciles. Declined: one project, and its owner was in the room for all of it.
5. **The `gh`-shaped silence** in `sync_states` and `pull_requests`, above. Declined because both
   of this owner's machines have a working `gh`. It is the third appearance of this class of defect
   and it will be the next one.
