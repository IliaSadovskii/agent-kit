# S8d — the door

Written after building it, 28 August 2026. The fourth step of the recovered layer and the
shortest of them, which was the point: it spends no session, so it has no provider, no contract,
no attempt chain, no room and no state of its own. Everything it reads is already on disk.

The promise it pays is older than the missed-layer section. §5 of the plan of 22 August named
the second version's defect — nine doors, each with its own checks — and promised **one door
instead of nine**. No step in the build order owned that promise, and nothing recorded what
became of the other eight. It was read as an answer for four days.

> **S8d · The door.** A program, not a session: it reads the runs, the batches, the open blocks,
> the red commands, the unanswered kinds and the open pull requests, and names one command with
> the reason. *Done when* a project after a week's silence gets one named command and the
> sentence behind it, and every part of that answer is derived from state rather than from
> anybody's word.

## 1 · The shape

`agent-kit next`. One module, one handler, no new noun, no new field, no migration. It prints
one block: the **answer** — a code, a command, one sentence — and beneath it the **view**,
everything else it found. That is what "one program rather than two" means: the ranked
recommendation and the raw survey are one pass over one set of data, where the second version
kept them in two places that had to agree.

The first line of the answer is a code, in the same shape a refusal names one, so a bench judge
checks a code and a command string rather than prose. The screen is English, like `doctor`,
`machine` and `run show`, whose place it took.

## 2 · The ladder, and the thing that nearly sank it

Six rungs, walked top to bottom; the answer is the first rung with something standing on it. No
weights, no score.

| # | rung | why it is above the next |
|---|---|---|
| 0 | a night is running here | mechanical: every command below would be refused by the lease |
| 1 | the night would refuse before its first session | mechanical: same |
| 2 | a run failed | a night spent with no result costs more than one not finished |
| 3 | work not finished — a batch, a stopped run, a created run, a run whose driver is gone | not finished costs more than a finished report |
| 4 | a pull request is waiting | a report costs more than emptiness |
| 5 | nothing is due | always fires, so the door always names one thing |

**The ladder did not descend, and that was the review's first finding.** `Run.reopen` refuses
everything but `stopped`, and `failed` is a final state — so nothing in the kit takes a run off
rung 2. A project whose night failed a month ago would have been told `run-failed` every evening
for the rest of the repository's life, and rungs 3 to 5 would never be reached again. The fix
uses what is already on disk: **rung 2 stands while the run's trace stands** — its worktree, or
for a hand-started run its `kit/<slug>` branch. `agent-kit tree remove` is the existing writer
that means *I have dealt with this*, and the kit's own rule already says the failed run's tree is
the only trace of how far it got.

**A batch owns a run's name, not its rank.** The first form suppressed every run a batch owns,
and `Batch.finished` means *nothing is running and nothing can start* rather than *everyone
landed*. Together they made a batch that lost a feature fall through to `nothing is due` — the
exact outcome the whole plan is written against. A failed feature stays on rung 2 now and is
named as `batch/feature`.

**A rung must not name a command the lease would refuse.** The first build asked the ledger only
for rung 0, so a run somebody was driving appeared again below with `agent-kit run go` — a
command that would be refused by name. The lease now takes the work off every rung.

## 3 · What it reads, and what a broken source costs

The project declaration, the knowledge, `runs/*/run.json`, the outputs of the `verify` and
`deliver` steps, `batches/*/batch.json`, the ledger, `PATH`, the audits' `candidates.md`, and
git. Two rules carry the whole of its robustness:

**One unreadable source does not hide the others.** Every source is read in its own `try` and a
failure becomes a named line in the view — `unreadable-run` with its path — rather than an
exception. The alternative, one `try` around everything, lets a `run.json` broken in March
silence the entire door.

**It never falls silent and never crashes.** An empty project — no runs, no batches, no
knowledge — gets rung 1 and `agent-kit knowledge tell`.

**It reads no clock for its ranking.** Not a single rung compares a record with *now*: the rule
that a fixture encodes a shape and not a moment cost the kit eight cases reddening every evening
after 17:00, and a door ranked by age would be the same defect in a command. The one clock in
the picture is the ledger's, which is asked whether a lease has expired — and the manifest says
so in those words rather than claiming the door reads no clock at all.

**It writes nothing.** Not a file, not a cache, not a "seen" mark. That turned out to need care:
`Ledger`'s constructor creates the database and its read path reaps expired rows, so merely
*asking* the door's question would have created the file it then reported as missing. It checks
the path before constructing, reads without reaping and without a write lock, and prints the code
the ledger itself named. `doctor` had the same defect and was fixed with it.

## 4 · The two git questions

Whether a pull request is open is known by the forge, and the door does not go to the network.
What it can know honestly is *a run opened a pull request on commit X*, and it can ask the local
repository whether X has landed.

One question was not enough. `merge-base --is-ancestor` cannot see a commit merged by **squash**
or rebase — and `gh pr merge --squash` is in the kit's own rules, so a project merging that way
would have sat on rung 4 for ever, with no way down. `git cherry <base> <branch>` catches both:
`-` means the patch is already there.

Three answers, and the third is real: yes (either question), not yet, and **not asked** — git
exited 128, there is no repository, the commit is unknown. A question that could not be asked is
not a refusal, so the rung stands and the text says which. The screen always says the forge was
not asked.

Both questions are put to the run's own base *and* to the trunk. A feature in a stack is based on
its parent's branch, so when the owner merges the stack into the trunk the patch never reaches
the parent — and the most common outcome of a batch would never have left rung 4.

## 5 · What died, what shrank, what lived

**Dead: `run list` and `batch list`.** They are literally the door's view — a line per run, a
line per batch — and keeping them means two more places that must agree with a third, which is
the defect §5 names. Measured before removing: four lines in two tests and one cell in an old
note; no trap, no judge, no plant script, no README, no Makefile. `RunStore.list()` and
`BatchStore.list()` live on with exactly one reader each — the door.

**Shrank: `doctor`.** It printed three unrelated questions at once. The ledger picture is
`machine`'s and the project half is now the door's; what stays is the one question that has no
other home — *what is this machine configured with and what is missing*.

**Lived, because they are different questions:** `machine` (what this machine is doing across
every project), `run show` / `batch show` (one thing in detail, with `--json`), `tree list`
(reads `git worktree`, a different source — a tree with no record behind it is invisible to the
door and visible there), `provider check` and `owner check` (they measure ladders and cost money
or network).

**Nine doors were never nine commands.** The defect §5 measured is a check hidden behind the
choice of a command, and most of that was answered by S2, S6, S7a and S8b putting each check
where it belongs and giving it a code. What the door pays is the other half: it names those codes
before the command is typed. Reading it as *you no longer have to choose a command* would be a
promise it does not keep.

## 6 · The numbers, measured by hand

| | before | after |
|---|---|---|
| `make test` | 1073 | **1116** |
| `make bench` | 103 of 103 | **112 of 112** |
| `make armed` | 98 + 5 in words | **107 + 5 in words** |

Nine traps added, none of them carrying `no_disarm`. All eighteen commits import and answer
`--help`.

**And one measurement of mine was void again, for the same reason as in S8c**: I started the
suite while the builder still owned the tree, and stopped it when I noticed. The numbers above
are from a stable tree. Twice in two steps is a pattern rather than a slip, and the answer is
simple — the verification run starts only after the builder reports.

## 7 · Breaking it by hand, and the two breaks that reddened nothing

| broken | what said so |
|---|---|
| rung 1 does not look at PATH | `a-project-that-cannot-run-a-night` |
| a failed run is never named | `a-feature-the-night-lost` |
| an unreadable `run.json` is skipped silently | `a-record-nobody-can-read` |
| an unfinished batch says nothing | `a-batch-nobody-started` |
| a run a batch owns is not suppressed | `a-batch-nobody-started` |
| the pull request is not read from `deliver` | `a-report-that-is-still-waiting` |
| only `--is-ancestor` is asked | `a-report-that-has-been-read` |
| the bottom rung stops answering | `a-project-nobody-has-run-in` |
| a stopped run is not named | `a-run-somebody-stopped` |
| a lease does not take the run off rung 3 | `a-night-that-is-running-right-now` |
| rung 0 stops answering | `a-night-that-is-running-right-now` |
| the trunk is not asked, only the base | **nothing** |
| a batch's feature is offered `run reopen` again | **nothing** |

The last two are the honest half of this step, and they are written into `door.py` itself rather
than only here. The bench cannot make a run with a base of its own — the base is set by the batch
driver, there is no command surface for it, and a `plant.sh` that edits `run.json` is the one
thing no agent in this kit may do. A judge that merges a branch itself plants a world the disarm
cannot take away. Three tests hold the trunk question (stack landed, stack not landed, branches
deleted) and one holds `batch reopen`.

Two judges had to be narrowed on the way, both because they read a neighbour's mechanism: one
asked what the door says about a landed run, which belongs to rung 4; one asked which rung
answered, which belongs to everything.

## 8 · Where the plan was wrong

1. **"Open blocks" as an input to the ranking.** A standing block has no command that closes it:
   `record` closes one inside a run, and the door cannot invent a brief. Naming one would be
   prose promising a check nobody performs — finding 53. It is a counter in the view, with
   `agent-kit knowledge tell` named beside it as the one closer that does exist on the command
   surface.
2. **"Open pull requests."** The forge knows; the door does not go to the network and prints what
   it did *not* ask.
3. **"One door instead of nine" is half paid by things that are not the door**, as §5 above.
4. **"Red commands" as a separate input.** There are two kinds and both already belong elsewhere:
   nothing to start with is rung 1, measured against PATH now rather than anybody's word; a
   command that returned non-zero is the *reason* on rung 2 or 3, because `verify` has a gate and
   the run already stopped.
5. **`doctor` is described in the plan as one page** while being a third place that had to agree
   with two others — the same defect §5 measures in the second version, standing in the plan's
   own command.

## 9 · What is held by tests and said in words, not by a trap

Rung 0 was in this list until the review pointed out that nothing measured it at all — no trap
and no words, which is the worse of the two. It has a trap now: the case plants a live lease by
hand (`slot hold --pid 1`, the same hand `the-machine-is-full` uses) and measures both halves —
that the rung answers, and that the same run is not offered underneath with `run go`.

What remains held by tests, each broken by hand and reddening nothing:

- the trunk asked beside the base, and `batch reopen` for a feature of a batch that has stood —
  both for the reasons in §7;
- an unreadable batch hiding only itself;
- `ledger-too-new` against `unreadable-ledger`;
- `doctor` no longer creating the ledger it then calls missing;
- `run-created` and `run-running` as rungs — the rung is measured by the stopped case, and a
  second world for a neighbouring status is another full run of the bench.

**Nothing here was driven by a live model**, and for the first time in this layer that sentence
is empty rather than honest: the door starts no session at all, so there is nothing a model could
have got wrong.

## 10 · What was deliberately not built

`--json` — no reader, and "someone will want it" is what rule 5 forbids; a cache or a state file
of its own; `next --all` and the ranked backlog, which the owner deferred with a reason that has
not expired; any network, any call to `gh`; any flag that makes the door *do* something — a door
that acts is not a door; an exit code carrying the rung (it always exits zero, including when the
project cannot be used at all: the door's answer is its output, and a door that refuses is a door
you can skip); a rung for the audit, which would make the door learn the lens's rules; reading
`debt.md`, whose lines have no command.

**Three seams named and not crossed.** S8e's catalogue of kinds: when it exists, rung 1 gains
`kind-unanswered: <kind>` from one source and the door's shape does not change. S8g's manual
actions: a rung between 3 and 4 reading a file that has no writer yet — and *the door names what
is due* stands in S8g's own *done when*, not this one. S8f's ledger of debt and the block kinds
without writers: the day a kind gains a closer with a command, it gains a rung and nothing else.
