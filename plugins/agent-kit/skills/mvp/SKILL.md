# MVP

Not written yet.

What it will be, so that the places already naming it read as a plan rather than as a gap: a layer
over the commands that exist. It composes the entries inside the MVP bounds into batches, runs each
batch the way `sprint` does, and stops when the bounds are built and the product starts. No new way
of building a feature — `ship` still builds every one of them.

Until it is written, `/agent-kit:sprint` is what does this, one batch at a time with the owner
composing each.
