# agent-kit — the third version

A console application for Linux that drives other people's CLI agents. The plan it is
built from is `docs/design/2026-08-22-the-third-kit.md`; read that before changing shape.

Commit messages and code in English. What the owner reads — pull requests, notes — in Russian.
The branch prefix for work the kit itself runs is `kit/`.

## Окружение

Ничего не ставится на хост: `uv`, Python и тесты живут в контейнере.

Тест упал без видимой причины — сначала посмотри `agent_kit.__file__`. Он обязан указывать
в `/app/src`. Всё, что запускало кит из копии дерева, могло переключить venv контейнера на
эту копию, и тогда тесты меряют код, которого в репозитории нет.

| Команда | Что делает |
|---|---|
| `make up` | собирает образ, поднимает контейнер, ставит зависимости (`uv sync`) |
| `make test` | `pytest` внутри контейнера |
| `make bench` | стенд: прогоняет подложенные ловушки и говорит, какие механизмы сработали |
| `make armed` | тот же стенд без ловушек: каждый случай обязан перестать срабатывать |
| `make install-check` | доказательство S0: `uv tool install` кладёт рабочую команду на PATH |
| `make shell` | приглашение внутри контейнера |
| `agent-kit next` | дверь: где стоит проект и что делать дальше — с этого начинают |
| `agent-kit setup` | вход для машины, на которой ничего нет: что запустить и что за это записано |
| `PYTHONPATH=/projects/agent-kit/src python3 -m agent_kit …` | запуск на хосте, где живёт настоящий `claude` |
| `make down` | гасит, кэши остаются |
| `make clean` | гасит и сносит тома |

Блок портов проекта — **8080-8089** (`ports claim agent-kit`). Занят один: **8080** —
страница демона, `agent-kit daemon start`. Слушает только петлю; наружу её отдаёт общий
прокси сервера, а туда попадают только через Tailscale.

Секрет пока один — токен телеграм-бота: `~/.local/state/agent-kit/secrets`, режим 600, не в git,
кладётся командой `agent-kit owner set-token` с потока ввода, а не аргументом. `config.toml`
секретов не держит и остаётся файлом, который не стыдно показать.

## Где что лежит

| Место | Владелец |
|---|---|
| `src/agent_kit/` | сам кит |
| `~/.config/agent-kit/config.toml` | выбор этой машины: аккаунты, модели, роли |
| `~/.local/state/agent-kit/` | что истинно прямо сейчас: логи, `daemon.sqlite`, `secrets` |
| `<проект>/.agent-kit/v3/project.toml` | что проект объявляет о себе: команды, ветка, роли; лежит в git |
| `<проект>/.agent-kit/v3/runs/<slug>/run.json` | состояние прогона; пишет только программа |
| `<проект>/.agent-kit/v3/batches/<имя>/batch.json` | состояние партии; пишет только драйвер партии |
| `<проект>/.agent-kit/v3/trees/<slug>/` | рабочая копия прогона — свой `git worktree`; в git не едет |
| `<проект>/.agent-kit/v3/audits/<линза>-<дата>/` | что намерила линза: опись, отчёт, список кандидатов; в git не едет |
| `<проект>/.agent-kit/v3/sittings/<дата>/` | час с владельцем: `telling.txt` дословно, ответы, бумаги двух ходов |
| каталог из `project.knowledge` (по умолчанию `<проект>/docs/knowledge/`) | знание проекта — владельца; кит только дописывает блоки шагом `record` |
| `bench/cases/<имя>/` | одна ловушка стенда: что подкладывается и что должно сработать |
| `/projects/kit-sandbox` | эталон для живых прогонов; `main` заморожен на `0e54eef` и не двигается |

`.agent-kit/runs/` — это вторая версия. Третья туда не смотрит и не пишет.

## Правила, которые уже действуют

- **Тест пишется первым, и это видно в истории.** Тесты идут своим коммитом — перед тем, который
  заставляет их проходить. Утверждать в сообщении коммита, что правило соблюдено, нельзя: это
  ровно то, что план называет «утверждение вместо следа».
- **Заявление вместо следа — это и про заметки, и про команды.** Написать «лестница держится»
  и не пройти лестницу; назвать в заметке правку файла, который не тронут; похвалить охранника,
  до которого не доходит исполнение. Всё это было в S7a. Что заметка о себе говорит, должно
  быть проверяемо тем же способом, каким проверяется механизм.
- **Состояние двигается только через программу.** Ни один агент не редактирует `run.json`.
- **Отказ называет причину.** У каждой ошибки есть код (`no-step-running`, `bad-field: status`),
  и код выхода означает одно и только одно — см. `src/agent_kit/errors.py`.
- **Поле без читателя не пишется.** Правило 5 из плана. `splittable` и `blocking` больше
  не исключения: у первого читатель — драйвер, который продолжает шаг, у второго — шаг
  доставки, который отказывает.
- **Шаг исполняет либо сессия, либо программа.** Программа — там, где ответ можно
  проверить, а не выслушать: `verify` сам гоняет команды проекта, `deliver` сам собирает
  ветку, коммит и pull request из уже записанного. Программа не провайдер: её никто не
  выбирает и не настраивает, и она не пишет себя в запись как модель.
- **Шаг может объявить `gate`** — поле своего же вывода, с `false` в котором прогон
  дальше не идёт. Сам шаг при этом прошёл: записать правду — и была его работа.
- **Pull request — отчёт владельцу.** Открыто три вещи: что сделано, что нужно от
  владельца, что мешает выпуску. Остальное — под спойлером.
- **Читать — не инструкция.** Всё, что шагу нужно прочесть, драйвер вкладывает во вход
  (`driver/compose.py`). Пропустить нечего, значит и проверять нечего.
- **Метод — проза в `method/`**, не пакет. Едет внутри wheel (`force-include` в `pyproject.toml`),
  проверяется целью `make install-check`.
- **Провайдера по имени не называет никто вне `providers/`.** Реестр читает папку: есть
  `provider.toml` — есть провайдер. Что верно про инструмент — в `provider.toml`; что выбрала
  эта машина — в `~/.config/agent-kit/config.toml`; ни один файл не держит чужое.
- **Уровень провайдера меряется, а не объявляется:** `agent-kit provider check <имя>` проходит
  лестницу и называет ступень, на которой споткнулся.
- **Формат знания — тот же, что у второй версии.** Блок это цитата markdown, первая строка
  которой называет вид, дату и прогон. Кит добавил ровно один сегмент — `id: k7f3q2`, — и он
  такого же вида, как `pr: 29`, который в этом формате был всегда. Ни одна старая строка не
  переписывается, мигрировать нечего.
- **Идентификатор блока выводится, а не бросается жребием.** Из имени прогона и слов самого
  допущения. Поэтому ловушка стенда может назвать его заранее, а вторая попытка переписывает
  свой блок, а не кладёт рядом второй.
- **Реестр долга пишет вечер, а не фича.** `<knowledge>/debt.md`: находку `worth-fixing`
  называет `record` (`debt` — ключ и слова), закрывает названную строку `design.fixes`, а кладёт
  и снимает строки драйвер партии — там же, где закрывает рамки, и в чекауте владельца, без
  коммита. Причина измерена: все фичи вечера ветвятся от одной базы, и две строки, дописанные
  в конец одной секции, — это две ветки, которые не сливаются, 200 раз из 200. Сортировка
  секции по ключу даёт 65% на одной строке и 2% на сотне — мерцающую ночь — и переписывает
  строки, которые владелец писал сам. Прогон, запущенный руками, в реестр не пишет вовсе: его
  находки остаются в pull request, и это сужение сказано в самом отчёте.
- **Дорогое допущение должно знанию блок.** Спрашивается дважды: проект, у которого знание
  есть, делает контракт шага `design` строже — отказ стоит одной сессии и называет поле; и
  ещё раз в `record`, что переживает прогон, собранный из других шагов. Проект без знания не
  должен ничего и выдумывать его не заставляют.
- **В знание пишет программа, а не сессия.** Модель возвращает поля, шаг `record` пишет файл
  и даёт блоку имя. Ни один агент не редактирует `docs/knowledge/` руками.
- **Вид блока без писателя не заводится.** Кит пишет `assumed` и `frame`: `found` — ревью,
  чьи находки в знание пока не идут, `stale` — тот, кто заметил. `accepted` выброшен: шаблон,
  блок и правило закрытия, и ни одного писателя за всю жизнь проекта.
- **Рамку пишет посадка, а закрывает та партия, что её написала.** `frame` — это то, что все
  фичи вечера строят одинаково, и потому его пишет `agent-kit batch compose`: единственный час,
  когда весь вечер виден сразу. Рамка — хореография, она живёт свою партию: драйвер снимает
  блоки, когда строить больше нечего, и только те, чьё имя в заголовке — его собственное. Ночь,
  остановленная человеком, рамки оставляет стоять. Прогон закрыть рамку не может (`record`
  отказывает по виду). Замер второй версии: рамка была там самым частым видом блока, а
  закрывателя у неё не было.
- **До `batch new` рамку не закрывает ничто.** Закрыватель один — драйвер партии, и он читает
  `batch.json`. Составили вечер и не набрали `batch new` — блоки стоят. Что подметает сама
  посадка, это только рамки того же вечера, которые он перестал называть: иначе вторая сборка
  оставляла бы сироту, на которого уже никто не сошлётся.
- **Вечер собирается с владельцем, а не набирается в TOML.** `agent-kit batch compose <имя>` —
  тот же сеанс, что `knowledge tell`, с другим чтением и другой записью: общее лежит в
  `sitting/room.py`, а два маленьких драйвера поверх. Артефакт остаётся один — объявление, — и
  дверь на граф остаётся одна: `batch new`.
- **Ворота стоят там, где партия создаётся.** Границы MVP, конец у каждого сценария и хотя бы
  одна объявленная команда проекта: `batch/gate.py`, одна функция, два вызывателя — `compose`
  спрашивает до первой сессии, `batch new` отказывает до того, как создана партия, прогон или
  дерево. Кода `no-commands` не заводили нового: это тот же код, которым отказывает `verify`.
  Каталога видов проверки тут нет — он ждёт S8e, и ворота его не заменяют.
- **Годится ли работа к сдаче — спрашивается до того, как что-то записано.** Блокирующая
  находка, красные тесты, недоделанная сборка: `programs/deliverable.py`, и первым спрашивает
  `record`, а не `deliver`. Знание владельца не трогают ради работы, которая не выйдет.
- **Заявление проверяется стендом.** `make bench` — сто сорок две ловушки, каждая делает свой
  репозиторий и сносит его. Меняешь механизм — сначала посмотри, какая ловушка про него, и
  сломай её нарочно: если не сработала ровно одна, ловушка меряет не то. Стенд ничего не стоит
  (отвечает `providers/fake/`, а не живая модель) и потому гоняется на каждое изменение.
- **Новый механизм заводит ловушку сразу.** Тесты — не замена: в S6 два механизма уехали
  сломанными именно так, тесты были, ловушки не было. Если ловушку не выходит поставить —
  напиши это в заметке словами, а не считай механизм проверенным.
- **Ловушка без ловушки обязана молчать.** Слом руками держался на человеке и трижды не
  сработал. `agent-kit bench disarm` (`make armed`) отнимает у случая всё, что он
  подкладывает поверх базового мира — `plant.sh`, `repo/`, `replies/`, — и требует, чтобы
  случай перестал срабатывать. `case.toml` не трогается: это вопрос случая, а не ловушка.
  Ответов четыре, и «не смог проверить» никогда не читается как «ловушка стоит». Случаю,
  у которого честного разоружения нет, поле `no_disarm` даёт сказать это словами — и слова
  печатаются на каждом прогоне проверки, а не лежат в заметке.
- **Новая ловушка проверяется сломом, а не рассуждением.** Пока механизм под ней не сломан
  руками и она не покраснела, ловушки нет. В S7a две новые были зелёными против сломанного
  кита: одна подкладывала строку, которую прогон выметал раньше, чем до неё доходил, вторая
  роняла канал фоновым сторожем, гонявшимся с прогоном. Обе «работали» до первого слома.
- **Перед кругом ломания — коммит, и во время круга дерево не трогают.** Иначе `git checkout`
  между сломами выбрасывает несохранённое, а в историю уезжает нарочно сломанная строка;
  случалось и то, и другое.
- **Зелёный только в рабочей копии не считается.** Перед сдачей распакуй `git archive HEAD`
  в стороне и прогони стенд оттуда: `.gitignore` однажды уже съел файлы ловушек.
- **Ловушка доказывает, что она стояла.** Судья, который сверяет «ничего не случилось»,
  зелёный и там, где ловушки не было вовсе. Сначала он показывает, что ловушка сработала
  (файл не пуст, ветка была до прогона), и только потом судит.
- **Случай сверяет код отказа, а не фразу — на любом языке.** Прозу перепишут, и случай станет
  мерить предложение. Нет кода у отказа — заведи код, а не подстроку. В S7a три судьи мерили
  русскую прозу кита, и перепись одного слова красила стенд без причины.
- **Фикстура кодирует форму, а не момент.** Час, записанный в тест как есть, делает случай
  зелёным до этого часа и красным после: так восемь случаев краснели каждый день после 17:00.
  Нужен час — считай его вперёд от прогона и сохраняй форму, а не дату.
- **Стенд подчиняется правилам кита.** Код 6 — механизм не сработал, код 7 — сам стенд не
  смог ответить; окружение случая — белый список, а не чёрный; всё, что стенд запускает,
  умирает вместе со своей группой процессов.
- **Ручное действие живёт в репозитории, а закрывает его доказательство.** То, чего ночь
  сделать не может — положить секрет, применить миграцию, завести аккаунт, направить домен, —
  фича называет в `design.manual`, `record` даёт ключ, а кладёт строку вечер партии:
  `.agent-kit/v3/manual.md`, чекаут владельца, незакоммичено. Писатель тот же и по той же
  причине, что у реестра долга, а место другое: проект может сказать `knowledge = ""`, и тогда
  знания у него нет — а непоставленный ключ нужен ему больше всех. Строку снимает
  `agent-kit manual check`: команда вернула ноль — строка ушла, и «сделано» перестало быть
  чьим-то словом о своей работе. Команда, которая не может провалиться, не запускается и не
  снимает ничего.
- **Строку, которую кит снять не может, дверь не ранжирует.** Строку с `by-hand:` закрывает
  только человек своей рукой; такие считаются в виде двери и не стоят на ступени: ступень,
  которую нечем снять, останавливает спуск двери — тот самый дефект, что ревью нашло у
  `run-failed`. Стадии проекта на диске нет, и заводить её значит завести поле с читателем,
  но без писателя и закрывателя.
- **Ранжирует и запускает одно и то же поле — `proof:`.** Файл правит рука, гейта на чтении
  нет, поэтому строка может нести оба сегмента или ни одного. С обоими — дверь её ранжирует,
  значит обход обязан её запустить, иначе это ступень, которую нечем снять. Без обоих — не
  запускается никогда: пустая команда возвращает ноль, и кит стёр бы то, что владелец записал
  себе сам. Записать такую строку нельзя (`action-with-no-answer`): пустой сегмент обратно
  не читается.
- **Потолок машины держит файл, а не процесс.** Слоты, лимиты, очередь и просьбы
  остановиться живут в `~/.local/state/agent-kit/daemon.sqlite`; каждый драйвер пишет туда
  сам, в транзакции. Демон отдаёт страницу и подметает мёртвое — потолок, который держится,
  только пока жив процесс, выключен ровно в тот час, ради которого заведён.
- **Слот — это одна живая сессия.** Берётся перед запуском сессии, отдаётся в `finally`.
  Шаг-программа слота не занимает: слот считает сессии, чья цена — квота. Лимит привязан
  к аккаунту (`providers.<имя>.account`), а не к провайдеру: одна подписка — один пул.
- **Занятая машина не трогает состояние прогона.** Ни одной сессии не запущено, шаг остался
  `pending`, код выхода 4. Провал прогона — это когда кит не смог сделать работу, а тут он
  её и не начинал.
- **Остановку прогона читает его собственный драйвер.** `run stop` при живом драйвере кладёт
  просьбу в базу, а не пишет `run.json` под тем, кто его пишет. Драйвер читает её на границе
  шагов и останавливает прогон сам; код выхода 130 — «остановил человек», а не «метод отказал».
- **Вопрос владельцу — поле шага, а не разговор.** Шаг объявляет `asks`: вопрос, и рядом
  умолчание, вокруг которого он уже всё спроектировал. Умолчание обязательно — вопрос без
  него это шаг, который отказывается закончить. Драйвер отправляет вопрос, ждёт свои двадцать
  минут и либо перезапускает шаг с ответом внутри входа, либо берёт умолчание. Круг — один:
  второй круг это разговор, а все передачи в ките — файлы.
- **`asks.json` — запись шага, а не счётчик кругов.** Оттуда драйвер, поднявший шаг заново,
  читает и ответы владельца, и уже взятые умолчания. Свёртка берёт всё, чем шаг когда-либо
  кончил спрашивать, а не последний круг: иначе умолчание, взятое в первом круге, не
  попадает никуда — ревью нашло ровно это.
- **У каждого исхода вопроса свой код.** `answered`, `nobody-answered`, `channel-failed`,
  `no-channel`, `had-their-round`. Записать «никто не ответил» про сообщение, которое не
  отправляли, — это неправда в знании владельца, и судья стенда сверяет код, а не фразу.
- **Круг, оборванный человеком, не потрачен.** Он и остановил ночь затем, чтобы ответить.
- **Ожидание — состояние шага.** `asking`, схема 3. Слот шаг при этом не держит (слот считает
  живые сессии, а сессия закрыта), а прогон держит — поэтому `run stop` до него доходит.
- **Умолчание, которое никто не подтвердил, — дорогое допущение.** Драйвер вкладывает его
  в вывод самого шага, и дальше всё уже умеет: `record` пишет блок в знание, `deliver`
  печатает его в открытой половине pull request. Честность этой дописи держит `raw.txt` —
  там лежит то, что сказала модель, нетронутым.
- **Канал не роняет ночь.** Нет канала, неверный токен, телеграм лёг — умолчание берётся,
  прогон идёт дальше, и в записи разные слова: «никто не ответил» и «до канала не достучались».
  Проверяют канал руками: `agent-kit owner check` проходит лестницу — канал настроен,
  канал отвечает, сообщение ушло, ответы читаются — и называет ступень, на которой встал.
  Код 8 — владельца не дозваться; это не код 4, потому что «агента не запустить» и «до
  человека не достучаться» требуют разных действий.
- **В чате нет кнопок.** Ответить на вопрос можно, командовать нельзя: идентификатор чата —
  это не аутентификация, а `agent-kit run stop` уже есть и знает, кто держит прогон.
- **Ответ владельца — это текст, а не инструкция.** Он приходит в шаг вложением, как вывод
  предыдущего шага, и ничто в нём не называет файл, команду или шаг.
- **Прогон строит в своей рабочей копии.** `git worktree` на прогон: свой HEAD, свой индекс, свои
  файлы. Бумаги прогона — `run.json`, каталоги шагов, `pull-request.md` — остаются в проекте, работа
  идёт в дереве: там же сессия, там же команды `verify`, там же коммит `deliver`. Дерево прогона,
  который дошёл до конца, сносится — это копия ветки; дерево упавшего остаётся, это единственный
  след того, как далеко он зашёл.
- **Партия — это граф прогонов, а не новая сущность.** Файл-объявление пишет владелец, `batch.json`
  пишет программа, каждая фича — обычный прогон со своим драйвером-процессом. Ниже партии никто о
  ней не знает: ни драйвер шага, ни адаптер, ни реестр машины. Если что-то снизу пришлось научить
  слову «партия» — форма выбрана неверно.
- **Фича ждёт одного.** Она растёт из ветки того, что ей нужно, и туда же открывает pull request, а
  у pull request одна база. Два ожидания — это слияние двух веток в третью, то есть кит пишет
  merge, которого никто не ревьюил: отказ `needs-more-than-one` называет это вслух.
- **Кит ничего не сливает.** В конце партии он проверяет в выброшенном дереве, сольются ли ветки, и
  называет пару и файл. Кнопка слияния остаётся владельцу.
- **Skip — слово партии.** Вне партии нет ночи, из которой можно вынуть фичу: одиночный прогон
  останавливают. Пропущенная фича уводит за собой то, что её ждало, и это печатается в тот момент,
  когда команду набрали, а не потом в отчёте.
- **Одно сообщение на партию, а не на фичу.** Ребёнку драйвер передаёт `--silent`: за него говорит
  партия. Вопрос владельцу это не трогает — у вопроса свой срок против человека.
- **Очередь решает «кто попросил раньше», через все аккаунты.** Потолок машины держит всех одинаково,
  поэтому в очереди стоит вся очередь; лимит и потолок провайдера держат один аккаунт, и отказ
  называет то, что мешает именно этой просьбе.
- **Три отказа держит `pre-push`, а не обещание.** Хук пишет `agent-kit init` и каждый
  прогон: `.git/hooks` не едет в git, поэтому у клона проекта хука нет. Дерево прогона
  делит хук с репозиторием, значит один файл покрывает все прогоны. Отказ называет код —
  `push-to-the-trunk`, `force-push`, — и это то, что читает судья. Чужой хук не
  переписывается: кит говорит, что нашёл. `gh pr merge` — не push, его не видит ни один
  хук; эту треть держит `method/rules/repository.md`, который несёт каждая роль.
- **У рабочей копии один писатель.** У прогона в партии своё дерево; у прогона, запущенного
  руками, дерева нет — он строит в копии проекта и держит её (`hold_checkout`). Второй
  такой отказан по имени: `checkout-held-elsewhere`, код выхода 3, состояние прогона не
  тронуто. Чего это не покрывает: одиночный прогон по-прежнему уводит HEAD владельца на
  `kit/<slug>` — он для того и запущен руками.
- **Результат привязан к дереву, на котором его мерили.** `verify` записывает коммит, на
  котором стояла рабочая копия, и каждое изменение сверх него — путём и содержимым
  (`programs/proved.py`). `deliver` отказывает, если в коммит попало то, по чему команды не
  ходили (`not-what-was-verified`), или если дерево с тех пор уехало (`tree-moved-since-verify`).
  Обратную сторону — измеренное, которого в коммите нет, — он печатает в pull request, а не
  отказывает: рабочая копия законно держит то, к чему фича отношения не имеет, и отказ здесь
  стоил бы ночи ради предложения.
- **Порядок шагов — довод, а не привычка.** `verify` перед своим `build` гоняет тесты проекта
  по дереву без нового кода: зелено по построению, и все, кто читает потом, видят `passed: true`.
  Порядок проверяется там, где прогон создаётся (`steps-out-of-order`, `step-twice`); `probe`
  в последовательность метода не входит и ей не связан.
- **Пустой список — ответ только там, где поле так и говорит.** `empty_is_an_answer=False` у
  `changes`, `files`, `tests` — и у `proves`, которому это ставит не поле, а проект, отвечающий
  на вид проверки командой: замысел, который ничем не докажет, ничего не решил, а сборка без
  тестов тестов не писала. У всего остального пустой список — настоящий ответ, и различие
  «подумал и не нашёл» против «не ответил» держится именно на этом.
- **Команда, которую нечем запустить, отказывается до траты.** Первое слово каждой объявленной
  команды ищется на PATH один раз перед первым шагом — и только у прогона, где есть `verify`,
  единственный её читатель. Код 2, состояние прогона не тронуто. Чего это не ловит: `make` без
  makefile на PATH есть, и это по-прежнему находит `verify`.
- **Открытая половина отчёта имеет потолок.** Документу, которому не назвали длину, длину
  придумывает модель: вторая версия намеряла тело в 45 000 знаков там, где о краткости просили
  прозой. `OPEN` в `programs/deliver.py` — это знаки на один открытый раздел, а разделов четыре:
  вместе выходит то же число, что вторая версия намеряла на всю открытую половину. Потолок у
  каждого раздела свой, потому что общий даёт прозе «Что сделано» съесть место у блокеров и у
  вопросов владельцу. И он режет, а не отказывает: остаток уезжает под тот же спойлер, а ночь,
  забракованная на последнем шаге за длину своего отчёта, — исход хуже длинного отчёта.
- **Между попытками — пауза, и она растёт.** Провайдер, которого на минуту завалило, отвечает
  так же и сессии, запущенной секундой позже: цепь без паузы тратит все свои попытки за то
  время, за которое стартуют три сессии. Число — `machine.backoff`, тридцать секунд с удвоением;
  своего потолка у удвоения нет, его держит потолок попыток. Ждут только отказы самого
  инструмента: ответ, не прошедший контракт, чинит вложенная в следующий вход причина, а не
  минута ожидания. Отдельного кода для «провайдера завалило» кит не заводит — какая сторона
  отказала, он и так знает, а узнавать это по списку фраз запрещает правило про код вместо фразы.
- **Аудит ничего не меняет, и это снятая возможность, а не обещание.** Сессия линзы стоит
  в распакованном `git archive HEAD`, и распакован он **вне репозитория**: git ищет
  репозиторий вверх по дереву, поэтому копия внутри `.agent-kit/` нашла бы `.git` проекта
  через два каталога, и коммит, ветка и push вернулись бы. Что распаковка вправду снаружи —
  спрашивается (`tree-inside-a-repository`), а не предполагается. Файлы пишет программа;
  каталог аудитов в git не едет, поэтому «ничего не изменилось» читается одной командой.
- **Находка линзы называет только измеренное.** Программа считает опись до первого вопроса
  и кладёт её на диск; сессия даёт строку каждой записи описи; программа сверяет вердикт
  арифметикой. Пропустить запись нельзя — `not-accounted-for`; назвать то, чего в описи
  нет, нельзя — `not-declared`; назвать импортируемое ненужным нельзя —
  `verdict-against-the-inventory`. Выдумать находку структурно нечем, и это то, чем
  «линза, ничего не нашедшая, говорит об этом» отличается от обещания.
- **Неповеряемое печатается, а не прячется, и его два.** Первое — «нужно, но не
  импортируется»: плагин, линтер, бэкенд сборки. Второе — привязка модуля к пакету, чьё имя
  с ним не совпадает: `PyYAML` вправду приезжает как `yaml`, и точно так же выглядит чужой
  импорт, подвешенный к чужому пакету. Первое даёт выдумать пустую работу, второе — спрятать
  настоящую, и это опаснее. Оба обязаны причиной (`no-reason-to-remove`) и стоят в отчёте
  открытыми счётчиками рядом с находками; измеренный модуль принадлежит одному пакету
  (`named-twice`), а строка `imported` не может назвать модуль, которого в описи нет
  (`not-declared`).
- **У аудита нет своей записи состояния.** Он не возобновляется, его нельзя остановить
  снаружи и у него нет графа — та же причина, по которой её нет у сеанса. Аудит это третий,
  кто зовёт `driver/session.py`, и ниже него никто не знает слова «аудит».
- **Провалившийся прогон не возобновляется молча.** `failed` — конечное состояние, причина
  остаётся в записи. Отказ одной попытки (`refuse_step`) и провал шага (`fail_step`) — разные
  события, и слова у них разные.
- **Где стоит проект — спрашивают у двери, и она одна.** `agent-kit next` читает то, что уже
  лежит на диске, и отвечает первой ступенью неизменной лестницы, на которой что-то стоит.
  Сырой вид и рекомендация — один проход по одним данным: вторая версия держала их в двух
  местах, которые обязаны были совпадать. Поэтому `run list` и `batch list` сняты, а `doctor`
  отвечает теперь на один вопрос — чем настроена эта машина. `run show`, `batch show`,
  `machine` и `tree list` остались: это другие вопросы.
- **Дверь называет чужой код, а не свой синоним.** Состояние, по которому какая-нибудь команда
  уже отказывает по имени, печатается её кодом: `no-description`, `no-commands`,
  `no-such-command`, `unreadable-project`, `unreadable-batch`. Это и есть плата по §5 — «пропустил
  дверь, пропустил проверку» становится «дверь называет код каждой проверки до того, как команду
  набрали». Свои слова заводятся только там, где отказа нет, и выводятся из самой записи:
  `run-failed`, `run-stopped`, `run-created`, `run-running`.
- **Ни одна ступень двери не зависит от времени суток, и в сеть дверь не ходит.** Ответ, который
  меняется в полночь, не держит ни одна ловушка: по возрасту не ранжируется ничего, а две записи
  сравниваются между собой — этого хватает на разбивку ничьей. Часы читает только леджер, у
  которого спрашивают, не истекла ли аренда: это вопрос про «сейчас» по своей природе. Влита ли
  работа, спрашивается у этого чекаута дважды (`merge-base --is-ancestor` и `git cherry`, потому
  что squash не предок ничему), и оба вопроса умеют только **снять** ступень, никогда не поставить.
- **Дверь ничего не отказывает про проект.** Единственный её отказ — `not-a-directory`, путь,
  набранный неверно. Всё, что она нашла, — её вывод, а не код выхода: дверь, которая отказывает,
  это дверь, которую можно пропустить. Один нечитаемый источник называется по имени и не прячет
  остальные.
- **Ступень стоит, пока стоит след.** Провалившийся прогон — конечное состояние, снять его с
  лестницы нечем, поэтому он держится ровно столько, сколько стоит его дерево (а у прогона,
  запущенного руками, — ветка). `agent-kit tree remove` — это человек, сказавший «я это разобрал».
- **Партия владеет именем, а не рангом.** Прогон, которым владеет незаконченная партия, не
  называется отдельной строкой: его продолжает `batch go`. Но упавшая фича остаётся на своей
  ступени и печатается вместе с именем партии — `batch go` её уже не построит, и ночь, потерявшая
  фичу, не должна читаться как тихий проект.
- **Цепь попыток держится в одном месте.** Слот, растущая пауза, запасной провайдер, вложение
  причины отказа в следующий вход и бумаги попытки — это `driver/session.py`, и им пользуются
  и драйвер прогона, и сеанс с владельцем. Что значит начало, отказ и занятая машина для
  `run.json`, знает только драйвер: четыре обратных вызова. Второй экземпляр этой цепи — это
  копия механизма, у которой нет ни одной из дюжины ловушек, стерегущих первый.
- **Отсутствие описания — названное состояние, а не молчание.** Три состояния, не два. Проект
  описан: в объявленном каталоге стоит хотя бы одна адресуемая запись. Проект не описывается,
  и это сказано вслух: `knowledge = ""`, набранное человеком в файле, который лежит в git.
  И молчание — отказ `no-description`, код 2, до первой сессии, и только у прогона, где есть
  `design`, единственный читатель. У отказа один код и три двери: `agent-kit init`,
  `agent-kit knowledge tell`, `knowledge = ""`. `keeps_knowledge` больше не вынюхивает
  каталог — это вынюхивание и было молчанием, из-за него кит меньше всего спрашивал
  у проекта, о котором меньше всего знает. Пустое значение — состояние, а не путь:
  `Path(root) / ""` — это сама рабочая копия.
- **Час с владельцем держит кит, а не привязанный к терминалу CLI.** `agent-kit knowledge tell`.
  Слова владельца идут через тот же безголовый ход, что и любой шаг прогона: есть `raw.txt`,
  есть контракт, есть след. Привязанный терминал не даёт ничего из этого и вдобавок не водится
  стендом, а форма, которую не водит стенд, — форма без ловушек.
- **Прослеживаемость — это отнятая возможность, а не проверка.** `said` — диапазон строк
  (`L12-L14`) в рассказе, который кит пронумеровал и записал дословно раньше, чем что-либо
  спросил. Цитату сверять не надо, кавычки и «ё» ничего не ломают, а указать на слова, которых
  никто не говорил, нечем.
- **Чтение полное, и это считает программа.** Каждая стоящая часть получает строку, включая
  те, что не двинулись: дешёвый способ выглядеть дотошным — прочесть треть и уверенно назвать
  три различия, и ровно этого строка на часть не позволяет. `reading-misses-a-part` называет
  ту часть, которой не хватило.
- **Спрашиваются только противоречия, и круг один.** Умолчаний здесь нет: двадцать минут S7a
  существуют потому, что ночью спросить некого, а это тот час, когда человек стоит рядом.
  Рассказ приходит файлом, ответы — только потоком ввода; поток закрылся при стоящем
  противоречии — `nobody-to-ask`, код 8, и не написано ничего.
- **Часть продукта — пункт списка с меткой.** Так писала вторая версия, и ни одна её строка не
  переписывается. Ключ добавлен сегментом того же вида, какой строка уже несёт:
  `` `key: sign-in` · `walked: 2026-08-27` ``. Часть находится по метке, а не по заголовку над
  ней: имя раздела — слово одного проекта, и читатель, который на него смотрит, слепнет в день
  переименования. Ключ выводится из имени части там, где строка его не несёт, и пишется в
  строку там, где часть пишет кит: второй рассказ переименовывает, а ключ, выводимый каждый
  раз, прочёл бы переименованную часть как новую.
- **Описание кит не коммитит.** Владелец стоит рядом и читает diff сам; сеанс на `main`,
  который коммитит и пушит, — это кит, ломающий собственный `pre-push`.
- **Реестр — не описание.** `debt.md` держит списком то, что построено и работает плохо или
  не работает вовсе. У строки реестра есть ключ и нет метки, поэтому частью продукта она не
  становится; а сам файл не считается в «описан», хотя его заголовки — обычные адресуемые
  записи. Иначе час, потраченный на одни жалобы, оставлял бы проект, который гейт считает
  описанным, а не описал никто. Назвать `debt.md` в этой проверке можно, потому что это имя
  кита, а не слово языка проекта.
- **Кит печатает команды и не запускает ни одной.** Ни установку, ни логин: поставить
  инструмент — дело владельца на его машине, а логин открывает браузер. Установщик,
  доложивший «готово», — это заявление вместо следа; напечатанная команда, после которой
  заново меряют, — след. Что напечатать, объявляет сам провайдер: `[provider.setup]` в
  `provider.toml`, два поля и оба argv.
- **Команду, которую кит не запускает, держат форма и перемер.** Форма — argv, а не проза:
  у списка слов берётся первое и спрашивается у PATH, у предложения — нечего. Перемер —
  та же даровая ступень `binary` после того, как человек сказал «сделал»: установка,
  вышедшая нулём и не поставившая ничего, оставляет ступень на месте, и тогда не пишется
  ничего. Полей, которые нечем перемерить, в блоке нет — `root` не заведён: `npm i -g` на
  одной машине требует root, на другой нет, и кит этого не знает.
- **Логин кит не объявляет пройденным.** Он его печатает. Отвечает ли аккаунт — платная
  ступень, и последней строкой ход называет `agent-kit provider check <имя>`: блок пишется
  на силе даровых ступеней, и без этой строки машина, где инструмент стоит, а аккаунт
  молчит, не сказала бы человеку ничего.
- **`setup` не тратит, `check` тратит.** Это вся граница между ними. Поверхность управления
  не требует живой модели, а это она и есть; поэтому у хода нет ни сессии, ни контракта, ни
  комнаты, ни проекта — он работает там, где репозитория нет.
- **Одно чтение, два экрана.** `doctor` показывает, где стоит машина, `setup` то же самое
  показывает и меняет. Второй проход по тем же строкам — это дефект §5, поэтому
  `agent-kit provider list` снят: он был третьим. У `check.Rung` один вид и один читатель
  каждой ступени, так что напечатанное и измеренное разойтись не могут.
- **Умолчание провайдера — строка, а не девять блоков.** `machine.provider`, читатель —
  `default_provider` в `driver/session.py`. Девять сгенерированных `[roles.*]` устаревают
  в тот день, когда шаг объявит десятую роль: старая машина откажет посреди ночи за роль,
  которую некому было вписать. Строка `doctor` про «every role falls back to the default»
  до этого ключа была неправдой.
- **Переписывается ровно свой блок конфига, и он собирается заново.** `config.write_block`,
  один писатель на все блоки; `[owner]` — его вызыватель. Чего это не обещает, сказано в
  самом коде: строка и комментарий **внутри** переписываемого блока не переживают запись.
  Построчное слияние держало бы больше, но честно оно не выходит — значение бывает
  многострочным, а у комментария ключа нет вовсе. Всё вне блока цело, и блок остаётся на
  своём месте: блок, уезжающий в конец файла, — это перестановка чужих строк.
- **Конфиг, который не разбирается, не переписывается.** `unreadable-config`, код 2, до
  того как что-то напечатано и задолго до того, как что-то записано.
- **Дверь спрашивает машину раньше проекта.** Ступень 1 получила `no-provider` и
  `unknown-provider` — оба кода чужие, из `driver/session.py`. Довод не «в таком порядке их
  поднимает кит», а правило самой двери: ступень не называет команду, которую откажут.
  `knowledge tell` на машине без провайдера не описывает ничего — он падает на первой
  сессии. Конфиг дверь читает в своём `try`, как и всякий источник: сломанный редактором
  файл машины не заглушает целый проект.
- **Комната сеанса в git не едет.** Там лежит час чужой речи дословно, ответы владельца и
  сырой текст каждой попытки, а кончается сеанс просьбой прочитать diff и закоммитить. Свой
  `.gitignore`, как у `runs/`.
